# NobleDNS 手机实测快速开始

> 这份说明是给日常使用者的简化版。它不要求你分析域名，也不要求你修改规则。
> **目前 NobleDNS 尚未获得真实手机 A/B 兼容性测试结论。** 本流程只收集证据，不会自动修改或放宽规则。

## 你只需要做两轮

### 第一轮：不开 NobleDNS（基线）

1. 在 AdGuard 中暂时关闭 NobleDNS 这一个 DNS 规则订阅。
2. 其他 DNS 服务器、网络和 AdGuard 设置都保持不变。
3. 在同一网络下，依次打开你平时常用的应用，完成下面的普通操作。
4. 记下是否正常；不要进行真实付款、转账或下单。

### 第二轮：开启 NobleDNS

1. 重新启用 NobleDNS 订阅，确认 AdGuard 显示订阅已更新。
2. 不更换 DNS 服务器，不改变其他过滤规则。
3. 重新执行同样的应用操作。
4. 如果出现异常，先不要改规则，打开 AdGuard 的请求日志，找出异常时间附近被拦截的域名。

## 建议先测这些日常功能

| 应用类别 | 只需完成的普通操作 | 不要做的事 |
|---|---|---|
| 微信 | 打开、收发消息、语音/视频通话连接 | 不需要转账 |
| 支付宝 | 打开、登录、进入扫码或账单页面 | 不要真实付款 |
| 淘宝/京东 | 搜索商品、打开详情、加入购物车 | 不要提交真实订单 |
| 抖音 | 刷推荐、播放视频、打开评论 | 不需要直播打赏 |
| 高德/百度地图 | 搜索地点、规划路线、加载地图 | 不需要实际出行 |
| 中国电信营业厅 | 打开、登录、查看套餐或账单页面 | 不要办理付费业务 |

只测试你实际安装和使用的应用即可；没有安装的不用补装。

## 如果发现异常，给我这三样就够了

1. 哪个应用、哪个操作失败。
2. 关闭 NobleDNS 时是否正常，开启后是否重复失败。
3. AdGuard 请求日志中对应的被拦截域名和匹配规则截图。

截图请遮住手机号、账号、订单号、令牌和其他个人信息。不要上传完整浏览历史或含有隐私参数的 URL。

## 重要判定规则

- 一次失败不等于误杀。
- 只有“基线正常、开启 NobleDNS 后可重复失败、日志命中具体规则、临时只放行该域名后恢复”，才构成较强的规则归因证据。
- 真实支付、转账、下单、账号恢复等高风险操作，不要为了测试而故意制造失败。
- 测试通过只代表该设备、该应用版本、该地区和该网络下的这些任务通过，不代表所有设备都安全。
