# NobleDNS

**One balanced edition · Compatibility first · Independently maintained**

NobleDNS is an independently maintained DNS blocklist for everyday use, with mainland China network conditions as an important design consideration. It aims to reduce advertising, tracking and other unwanted DNS requests while preserving access to legitimate websites, apps and essential services.

We publish **one balanced edition**: one subscription and one consistent maintenance standard. The project prioritizes conservative rule scope, transparent sources and reproducible builds over maximum block counts.

## What it does

NobleDNS provides DNS-level filtering for advertising, tracking, telemetry and other unwanted domains represented by its configured sources.

- **Compatibility-conscious:** sign-in, payments, banking, messaging, push notifications, shopping, maps, video, updates and public services are important review priorities.
- **Conservative:** prefer appropriately scoped rules supported by evidence; do not treat maximum blocking volume as the goal.
- **Consistent:** one public edition means fixes and maintenance improvements apply to everyone.
- **Auditable:** source fingerprints, build manifests, validation reports and parser-exclusion records are published for inspection.

DNS filtering is one layer of protection. It cannot block every ad, particularly first-party ads, ads served from shared domains, or advertising embedded directly in apps and media.

“Mainland-oriented” and “compatibility-conscious” describe project priorities, not a claim that every mainland website or app has been tested. The project does not claim a measured real-world false-positive or blocking rate without a representative, independently reviewed benchmark.

## Sources and rule handling

The current build combines three complementary upstreams:

1. [AdGuard DNS Filter](https://adguardteam.github.io/AdGuardSDNSFilter/Filters/filter.txt) — broad DNS advertising and tracking coverage.
2. [HaGeZi Multi Normal](https://cdn.jsdelivr.net/gh/hagezi/dns-blocklists@latest/adblock/multi.txt) — broad balanced DNS protection.
3. [AWAvenue Ads Rule — Ads-only AdGuard variant](https://raw.githubusercontent.com/TG-Twilight/AWAvenue-Ads-Rule/main/Filters/AWAvenue-Ads-Rule-Adguard-Only.Ads.txt) — a focused advertising source with additional attention to app and smart-device advertising scenarios.

NobleDNS deliberately uses AWAvenue’s Ads-only variant, not its broader privacy or unwelcome categories. This adds a focused advertising layer without importing its separate telemetry, push, update or other unwanted-connection categories. The compiler preserves supported AdGuard DNS hostname rules, including documented wildcard patterns with fixed suffix labels and the `$important` modifier. Unsupported or ambiguous syntax is recorded and excluded rather than rewritten. NobleDNS independently controls its build process and is not affiliated with or endorsed by any upstream project.

The compiled subscription contains supported rules parsed from the configured sources. Unsupported or complex syntax is excluded rather than guessed or silently rewritten. The main subscription also includes simple upstream exception rules accepted by the parser; these can override matching block rules in compatible clients. Upstream inclusion establishes provenance, not proof that an exception is necessary or correctly scoped. The 11 inherited entries currently present in the published build remain marked pending in the [exception review register](data/exception-review.csv); they have not been independently approved by NobleDNS. Active exceptions are listed separately for inspection.

A rule count is not a measure of quality, and inclusion in the compiled list does not mean every domain has been individually reviewed by NobleDNS.

## Build transparency

The following generated files are the source of truth for the current build. Their contents change as approved upstream sources change.

- [Build manifest](dist/manifest.json) — source fingerprints, counts, build metadata and policy.
- [Validation report](dist/validation-report.txt) — automated output checks.
- [Syntax audit](dist/syntax-audit.json) — supported rule forms and syntax inventory.
- [Parser exclusions](dist/parser-exclusions.csv) — source lines excluded by the parser.
- [Active upstream exceptions](dist/allowlist-active.txt) — simple exceptions present in the main subscription.

The project enforces a 500,000-rule ceiling, source-drift checks and automated regression tests. These controls reduce build and maintenance risk; they do not replace real-client compatibility testing or a representative real-world benchmark.

## Report a problem

If a website or app stops working, report the exact hostname, affected feature (for example sign-in, payment, push, playback or updates), DNS client and version, and reproducible steps through [GitHub Issues](https://github.com/LucentDNS/NobleDNS/issues).

Comparisons with NobleDNS enabled and disabled, keeping the resolver and other settings unchanged, are especially helpful. Remove personal information, account details, tokens and private data from logs before sharing. See the [feedback guide](docs/FEEDBACK.md).
