# Security Policy

## Scope

NobleDNS is a DNS filtering rule compilation project. Security reports may concern the build pipeline, source integrity, release authentication, dependency handling, repository credentials, or a rule that creates a material security or privacy risk.

## Reporting a vulnerability

Please do not publish exploit details, credentials, private keys, tokens, or sensitive reproduction data in a public issue or pull request.

If GitHub's **Report a vulnerability** option is available on the repository's Security tab, use that private reporting channel.

If private vulnerability reporting is not available, open a minimal public issue titled **"Security report — request for private contact"**. Include no exploit details or sensitive data; ask the maintainer to provide a private reporting channel.

## What to include

When a private channel is available, provide:

- A concise description of the suspected vulnerability and its potential impact.
- Affected workflow, file, release, or component.
- Reproduction steps or a proof of concept that avoids exposing real credentials or personal data.
- Any suggested mitigation, if known.

## Disclosure

Please allow the maintainer a reasonable opportunity to investigate and prepare a fix before public disclosure. Do not assume a response time or remediation deadline; the project is maintained on a best-effort basis.

Never send private keys, access tokens, passwords, or unredacted user DNS logs.
